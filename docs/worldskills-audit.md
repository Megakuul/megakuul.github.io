# WorldSkills audit · 2026-09-15

Reviewed the 2019, 2022 Special Edition and 2024 cloud-computing marking schemes in `~/Downloads/exports`. The table below uses worksheet row numbers from `WSC2024_53_Cloud_Computing_marking_scheme.xlsx`; repeated checks belong to different competition days. They are not a guaranteed score for a future competition.

Scope: 119 Powertools entries, including 48 base CloudFormation templates and 22 service-only alternatives; all 18 CodePipeline variants and their global WAF companion template; the checklist, Kubernetes, cloud-init, Lambda, AppSync and Step Functions examples.

## Corrections

- SQS now implements the advertised `.fifo` suffix: matching FIFO main queue/DLQ, content-based deduplication and a redrive allow policy restricted to the source queue. Standard queues omit FIFO attributes rather than sending `"null"` through the CLI.
- DynamoDB enables TTL on `expiresAt` (Number, Unix seconds). Items without this attribute remain permanent. The `pk`/`sk` key schema is unchanged.
- ECR service/pipeline templates have a TLS-only repository policy. It grants no additional access; scoped IAM pull/push authorization is still required. Pipeline repositories now have an untagged-image lifecycle policy.
- ECS pipelines have CPU target tracking with a 2–4 task range, S3/DynamoDB gateway endpoints and ECR API/DKR interface endpoints. ECR endpoint access is limited to the created repository and HTTPS from the task security group.
- ECS pipeline ALBs and the ASG ALB have an attached enforcing WAF and retained WAF logs. The standalone WAF now enforces managed rules, but its output must still be associated with an application. S3/EC2 pipeline commands automatically create a companion WAF stack in `us-east-1` and associate it with CloudFront.
- Added an RDS PostgreSQL preset: private Multi-AZ instance, TLS enforcement, encrypted storage, deletion protection, 14-day backups, snapshot tags, PostgreSQL/upgrade log exports, monitoring, alarms and an RDS-managed rotating master secret. This is a TCP database, not the Aurora Data API used by the Step Functions/AppSync examples.
- Lambda bootstrap tracing is enabled; its existing execution role needs the provided logging/X-Ray permissions. IoT audit/notification trust policies match same-account IoT source ARNs instead of an exact empty resource suffix.
- Kubernetes examples include EKS control-plane logging and restricted endpoint access. ALB ingress includes HTTPS, restricted client CIDR, WAF, logs and tags; the NLB also restricts client CIDRs. Karpenter and cloud-init launch examples enable detailed monitoring.
- The AppConfig ECS sidecar inherits the application's CloudWatch log configuration with its own stream prefix. The Lambda database deployment example now tags the function and creates a retained log group.
- CLI result extraction now propagates missing/invalid result fields instead of masking `jq` failures with `export`.

## Remaining application work

- Deploy real Lambda handlers and attach logging, tracing and workload permissions to supplied execution roles. Generic role cards deliberately create a trust policy and editable permissions policy; they do not grant every workload access. Configure asynchronous failure destinations where used.
- Associate reusable log destinations, WAFs and roles with existing resources. Confirm SNS subscriptions when notifications are wanted. Transfer users/SSH keys, Glue job/crawler attachment and application data permissions remain explicit setup steps.
- Replace the Kubernetes examples' client CIDR, certificate, WAF ARN and bucket; ensure the controller, add-ons, subnet discovery and workload identities are installed/configured.
- Keep the Aurora Data API enabled and use a supported Aurora engine/Region for AppSync/Step Functions RDS integrations. A regular RDS PostgreSQL endpoint is not interchangeable with a Data API cluster ARN.
- The reference collection does not provision complete Batch, Flink/Kinesis Analytics or VPC-peering workloads. Likewise, task-specific routes, database contents, application behavior, load tests and recovery exercises cannot be satisfied by toggles alone.
- The compute presets use one NAT gateway to limit competition costs; that is not resilient egress across AZ failures. The default CloudFront certificate supplies HTTPS but cannot enforce a custom minimum TLS policy; that requires an ACM certificate and custom hostname.

## Validation

- All 89 generated CloudFormation templates/alternatives pass `cfn-lint`, excluding only W3045 for ACLs required by CloudFront's legacy standard logging.
- 43 generic CLI scripts execute against mocked AWS, and 360 generated request payloads match Botocore service schemas. GuardDuty has separate new/existing/error-path tests. FIFO/standard SQS behavior and AppConfig sidecar transformation are checked separately.
- All 18 pipeline templates pass reference resolution, source/archive, approval, artifact and API-shape checks. Deployment and source-upload commands execute against mocked AWS, including existing-branch and access-denied cases.
- 22 Step Functions definitions validate; 26 documented input/output examples pass local evaluation, including JSONata, callback timeout/failure, empty maps and parameterized RDS requests.
- 19 AppSync JavaScript blocks pass the AWS runtime lint rules and 68+ local authorization/data-flow/error checks. All 17 GraphQL example operations validate against the shared schema.
- 84 Lambda JavaScript snippets and 72 Python snippets parse. The IoT/Transfer/Firehose/Glue/Scheduler/DataSync examples additionally have mocked request and failure-path checks. All 11 cloud-init documents and 25 Kubernetes snippets parse; embedded shell scripts pass `bash -n`.
- Svelte type checking and the production build pass; the existing `@apply` CSS warning remains. Browser tests verify deployment switches, copied commands/YAML, downloads and mobile overflow.

No resources were deployed to AWS during this audit. Static validation and mocks cannot verify service quotas, regional rollout, account restrictions, IAM propagation, live networking or the private competition checker.
