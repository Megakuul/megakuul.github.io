# Powertools Well-Architected review · 2026-09-18

Scope: all 125 entries returned by `powertoolsGroups()`: 53 base CloudFormation templates, 23 service-only alternatives, 44 native CLI alternatives, and the remaining environment commands and IAM policy examples. Reviewed generated resources, resource/IAM policies, encryption, logging, network access, availability, recovery, and operational defaults. CodePipeline and other WorldSkills pages are outside this review.

These are service bootstraps. A missing task definition or subscription is intentional; a configured service silently omitting its operational logs is a gap. A template alone cannot establish workload-wide Well-Architected compliance, recovery objectives, tested restores, application authorization, or appropriate capacity and spend.

## Fixed in this revision

- **ECS account defaults:** added regional enhanced Container Insights, ENI trunking and GuardDuty Runtime Monitoring with automatic Fargate agents. Preserves existing EC2/EKS agent settings; does not silently enable agents across non-ECS EC2 hosts. Prerequisites, rollout limits, costs and intentionally unchanged settings are documented in [ECS account defaults](ecs-account-defaults.md). Other GuardDuty protection plans and findings routing still require review.
- **ECS Action Logs:** added `EcsActionLogs` delivery source, JSON destination, delivery association and scoped log-write resource policy. These record deployment/orchestration actions; they are distinct from task output, Container Insights, ECS Exec transcripts and CloudTrail API auditing. Action Logs use a protected, retained 30-day log group. Delivery resources are retained with the retained cluster.
- **Customer-managed CloudWatch encryption:** all 57 explicitly provisioned log groups across 19 base templates now have KMS encryption, including ECS task/Insights/Exec/Action Logs, the standalone Logs card, Logging setup, and generated infrastructure/WAF groups. The same baseline reaches service-only downloads and native CLI commands. Each affected stack gets one tagged, symmetric, rotating key, retained with its logs. No extra input is required.
- **ECS cluster encryption:** configures separate rotating, retained keys for Exec sessions and managed/Fargate storage, in addition to the logging key. Fargate grants are restricted to this account/cluster and the required decrypt operation. Customer-managed ephemeral storage requires Linux platform 1.4.0 or later and applies to new tasks. ECS-managed EBS volumes still need the workload's infrastructure role and scoped KMS use/grant permissions.
- **ECS Exec:** enables the encrypted CloudWatch destination and the session key. Optional output policies grant task-role decrypt/SSM/log access and operator GenerateDataKey/ExecuteCommand access. Attach them to the intended roles; enable Exec on tasks, include `script`/`cat` in containers, and provide network access to SSM Messages, Logs and KMS. Service-only mode retains encryption but leaves these optional role policies to the caller.

CloudWatch Logs was already encrypted at rest with service-managed AES-GCM. Missing `KmsKeyId` meant no customer-managed key, not plaintext storage. KMS adds control and auditing, along with key/request costs. Retained keys continue to incur charges; disabling/deleting them makes their retained logs unreadable. Existing log data is not retroactively re-encrypted. Service-created groups outside these templates, such as RDS enhanced-monitoring `RDSOSMetrics`, are not changed.

The key policy limits the regional Logs service to the template's log-group encryption contexts. REST API execution logging needs an API-generated name: its context is limited to `API-Gateway-Execution-Logs_*/live` in the same account/Region to avoid a key → API → Lambda → log-group → key dependency cycle. Other contexts use the configured names. Split keys further if log groups have different data classifications.

## Validation

- `npm run check` and production build pass; existing CSS/Markdown warnings remain.
- All 76 generated Powertools templates/alternatives pass `cfn-lint` 1.57.0, excluding W3045 for the existing CloudFront legacy logging ACL.
- Regression checks cover every explicit log group in both CFN modes, ECS Action Logs wiring, native CLI encryption/delivery payloads using mocked AWS, and Bash syntax for every native command.
- No AWS resources were deployed. Live Action Logs delivery, KMS permissions under account SCPs, on-call notifications and recovery behavior require deployment validation.
